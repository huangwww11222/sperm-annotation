# 当前业务流程与不变量

此文是实现与回归的业务依据；字段、路由见 [API.md](API.md)，标注操作见 [ANNOTATION.md](ANNOTATION.md)。A/B/C 代表流程职责，**可以由同一账号完成**。服务端仍按任务领取人保护编辑，不允许抢占其他账号已领取的任务。

## 当前标注直接导出流程（2026-10-29）

用户已确认暂不送审。新标注页只保留首尾双向追踪，默认 edgeDiscovery=true；不再显示单向 AI Tracking 和入画开关。旧单向请求、暂停确认与重试保留兼容，未决请求重放原正文。

标注首尾帧 → 三路综合标注 → 人工检查/微调 → 标注页“导出训练数据集”。点击导出即准备当前快照，后台保存并读取服务端来源；完整时直接打开导出设置，无重复确认弹窗；未知帧必须补标或显式声明空帧，坐标、原视频、类别及最低帧数沿用现有导出校验。快照存于 annotation_export_snapshots，复用训练包队列，不创建 A/B/C/F 或虚构审查记录。新快照按账号隔离、版本绑定、原键重放；标注变化或原视频丢失后旧下载失效。历史任务入口、原始快照、审查与确认记录及其导出门槛保留，不能自动迁移为“已验收”。

下文两阶段与三阶段说明用于既有审查任务和接口兼容，不再是新标注页必经路径。

## 当前两阶段流程（2026-10-27）

### 人工首尾帧与双向追踪

推荐先在标注页完整框出首帧和尾帧的精子头，再点击“首尾双向追踪”，明确确认两端已完整检查（尾帧可以明确为空）。首尾编号可不同；尾帧仅有 AI 框不算人工端点，须人工绘制或修正。原“AI Tracking”继续提供从当前帧向后的单向续追，不自动推断尾帧已由人工检查。

独立人工尾帧通过 `terminalAnnotations` 固定在同一幂等追踪请求中。新页面同时发送 `combineResults=true`：正向从首帧开始，反向从人工尾帧开始，再结合检测器生成统一框。反向每窗口最多16帧、相邻窗口重叠1帧，边界使用反向 AI 续接，不追加人工确认。端点快照及策略哈希随结果保存，送审时随来源摘要冻结。旧请求省略 combineResults 或 false 时保留仅反向核验的兼容行为。

综合策略 `joint-head-v1`：只围绕已在追踪范围中的头部位置做原分辨率分块检测；候选必须局部且唯一关联，不把检测器发现的内部陌生目标自动新增。检测置信度>=0.7 才参与框修正，邻近对象或多候选竞争时不硬配。每个稳定身份从正向、反向、可信检测及近邻一致框中构造候选，通过整段动态规划选择连续路径，综合定位吻合、距人工端点远近、运动/尺度连续性及切换代价。只有位置已接近的框才可形成坐标中值，不平均不同头部的位置。正向漂移可选反向/检测，反向漂移可保留正向，双方偏松可由检测细化；已知身份缺框可用有观测的反向定位找回。人工框与删除墓碑优先；两方向均无观测时不插值、不凭检测器创建内部身份。

三路只在后台使用；标注页、AI 结果接口和送审 A 的 objects 均只有一套最终几何，不增加采用理由、多路框或来源指标的常驻展示。日志记录策略、数量及失败；疑点保留在审查证据。强支持修正后移除已失效的旧位置疑点，检查失败/身份不明不能按修正成功处理。局部检测不等于整图漏检检查，保留全图抽查及人工逐帧审查。

检测模型/依赖不可用、原图读取失败或结构错误导致综合任务失败，保存正向已发布成果及明确失败标记，不报告综合成功。空尾帧是明确的反向证据不足，使用其余观测生成候选并保留待审状态，不补造反向框。模型门限与路径权重是可回归的首版启发式，并非准确率保证。

旧仅核验模式按多帧平均 IoU 匹配。综合模式原 `joint-endpoints-v2` 要求实际端点位置匹配和至少3次共同位置支持（不足3帧按实际帧数），使用25%全段均值+75%最佳3次支持的均值，最佳与竞争候选需拉开0.15，最低分0.5。当前 `joint-endpoints-v3` 在此基础上，对因框松紧差异漏配的对象增加唯一多帧头部中心核验，并以完整人工尾帧决定端点输出；旧 v2 结果采用统一读取投影修复，原文件保留。这样长段正向漂移不会抹去已确定的端点联系；轨迹太短或歧义仍不硬配，更不靠相同编号强配。正常重叠本身不生成错误结论；综合后仍不确定的片段进入审查。尾帧未覆盖的中途出画对象、中途入画后又出画的对象保留待核对；边缘发现和全图漏标检查继续运行。

原始尾帧人工编号/几何保留在 Tracking 末帧锚点快照，送审时固定到不可变审查证据。唯一匹配后，标注页将尾帧局部编号统一为正向稳定身份，并记录 endpointOriginalObjectId / endpointAnchorHash，恢复或重读同一结果不重复转换；工作区按原版本/保存队列持久化。由此整段删除、续追、送审使用同一身份；人工尾框优先，不重复入库。尚未完成前端身份统一时，A 来源合并仍可使用原始尾帧映射，避免响应丢失导致重复。对应不明确时不强制合并或吞框。

首帧唯一回归及连续位置支持可以纠正后段共追邻居造成的旧尾帧错配；同一锚点哈希下，也须用保留的原始尾编号应用新对应，不能继续沿用错误 canonical ID。综合及历史读取共用边界退出保护：明确裁切向外运动、原图主体风险及持续借用已有邻居共同成立才终止AI身份；正常重叠、画内遮挡或检测器单次缺失不作为退出。原文件、人工端点和历史保留，结果API、JSONL与训练来源采用相同投影。详细边界见 ANNOTATION.md。

反向未完成、模型错误或明确空尾帧分别记录 failed/insufficient，不记通过；正向成果保留，审查页显示检查状态与疑点。所有帧仍须人工显式提交，再完成视频审查；双向一致和检查完成都不代表自动验收。

新页面送审使用 `concentratedReview=true`：人工标注头框 → SAM3 分段续追并收集疑点 → 审查页逐帧检查/纠错 → 显式完成审查，生成最终 F → 导出训练集。导航只显示标注、审查。下文 C 的选择/重审规则仅用于升级前的历史任务；旧任务不自动改状态，原始 A、历史 B/F 与操作记录不删除。

- 新 Tracking 请求 `reviewMode=true`。几何/重叠质量风险不再中断模型；每段仍受配置帧数限制，服务端以 AI 末帧为下一段提示自动续跑，不写成人工 seed 或人工确认。无法前进、模型/存储失败或整段末尾无可续追对象时明确失败，保留此前发布片段，不伪造空帧或补框。
- `review_evidence.py`：逐帧收集原图主体风险与对象缺失；每段首个后续帧及原始帧索引为 5 的倍数时全图分块检测。检测器缺失属于证据不足；位置/头部边界分歧、多个对象仅对应同一候选、未关联候选进入疑点，不自动增删标签。不依据 BBox 重叠或尺寸变化单独判错。
- 每段最多选 2 个疑难短片段、每段最多 8 帧做真实反向核验，以末帧 AI 框为反向提示。正反向框 IoU <0.5 仅作为疑点；一致也不是准确性证明。未运行、失败、检查完成分别记录，绝不缺省为通过。阈值和抽样属于首版启发式，尚无独立质量召回率验收。
- 所有框都在审查页显示；对象/原因相同的连续疑点合并，稀疏检测样本按相邻采样合并并保留原始采样帧。疑点定位不提交、不修框。无提示不等于正确，仍须整幅检查及每帧显式提交，包括漏标和空帧。
- 新审查完成在同一事务固定 B 和最终 F。为兼容既有 F/审计结构，内部仍使用 confirmation 存储，决定注明 `review-acceptance:explicit-video-completion`，表示审查员的显式最终验收，不代表另一位 C 点击。新任务拒绝旧 C 修改接口。
- 已完成任务可由原审查员“重新审查本帧”：旧 F、历史记录保留；当前最终指针清空、该帧重新待提交、旧包立即失去下载资格。其他帧提交保留；再次完成后仅最新 F 可导出。不能以放弃草稿代替重新提交。
- 未配置头部检测器、自动检查失败/证据不足在审查中明确显示。它不阻止人工完整检查后提交，但不表示自动质量验收通过。首次版本的审查修正只作用于本帧；大量追踪错误通过退回人工标注重追，不自动把单帧修正传播成已审查结果。

## 兼容的原三阶段流程与页面职责

```text
原视频 + 人工标注 + 已接受的 AI 追踪结果
  → 完成标注并送审：保存工作区、检查全帧覆盖、固定 A
  → B：修框/补标/删除本帧框 → 自动保存草稿 → 显式提交每帧
  → 全帧已提交 + 显式完成视频审查 → 固定完整 B 与净修改项
  → C：逐修改项保留 A / 采用 B → 即时保存决定
  → 全项已选择 + 显式完成视频确认 → 固定完整 F
  → 校验当前 F 与原视频 → 后台生成训练集 → 验证资格后下载
```

- **人工标注**：创建、删除、移动、缩放对象，逐帧检查，按当前帧 seed 进行 AI Tracking。
- **审查模式**：中间真实帧、缩放、播放、帧导航；右上撤销/提交和保存状态，右下本帧对象列表（全部/仅已调整/已删除/ID 搜索）。选中对象后按需展开同范围裁剪的 A/B 对比与几何详情，草稿入口也按需展开。允许移动、缩放、补标、删除本帧框及恢复；原 A 不改写，不改已有类别，不标记问题。常规增删无需填原因；整段返工可由当前审查员填写原因退回人工标注。
- **对比确认**：中间左侧为完整帧主图，旁边上下排列当前对象的 A/B 局部图，也可切换叠加，图下浏览上一/下一修改项。完整帧中金色外框只定位当前对象，A 紫色虚线/B 绿色实线对应旁边局部图；点击或用 Enter/Space 激活有修改的框，可同步切换局部图与右侧列表，不产生确认决定。完整帧可展开查看；页面不展示 IoU、位移和坐标等几何详情，指标仍保留在数据中用于追溯。右侧顺序为“确认本项”（A/B 选择、保存状态、撤销）→ 已完成时的训练集导出/重新确认 → 按帧分组的修改项列表，DOM 与视觉顺序一致。列表统一承担全视频导航和当前帧定位，支持全部/待确认/已确认、分页与定位当前项。处理 B 相对 A 的修框、补标和删除净变化，不生成第三种几何；A/B 任一侧可明确不存在对象。
- B/C **视频进度与完成按钮统一放在站点顶栏的工作区上下文中，专注时移到画布上方细栏**，B 展示真实提交进度，C 展示真实修改项选择进度；完整状态由任务与当前项数据提供。右上主操作与保存失败重试不随对象列表滚动。不能把正在浏览的帧号当已审查数量。
- **标注记录**：独立查询已入库人工新增/修改对象，按媒体身份区分同名文件，可搜索/分页。不是完整 AI 结果，不是 F，不是标注与审查之间必经步骤。
- **统计数据导出**：标注记录页的独立入口，导出全实例 A/B/C/F、人员和流程历史，包括未完成与历史版本，不受该页筛选影响。它是只读统计传输，不生成训练图片/标签，不修改视频完成状态，不绕过训练集准入。后台生成、本人查询/下载与原键恢复，不直接交付 app.db。
- **使用说明**：顶部入口打开对应页面章节，可搜索和下载完整说明。原生模态窗口隔离下层业务快捷键；关闭后恢复焦点和页面滚动。内容统一维护于 [用户手册](../frontend/src/help/user-guide.md)。

## 工作台布局与扩展规则

2026-10-24 起三页统一使用“画面优先”外壳 `components/WorkbenchShell.vue` + `workbench/shell.css`（取代 `WorkbenchHeader` / `WorkbenchLayout` / `WorkflowProgress` 的页面用法）：

| 区域 | 职责与约束 |
| --- | --- |
| 站点顶栏（48 px） | 阶段切换 + 页面上下文插槽 `#app-header-context`：视频身份、帧号/对象、真实状态、紧凑进度和阶段完成按钮（A 送审、B 完成视频审查、C 完成本视频确认）。专注模式下同一内容移到画布上方细栏 |
| 左侧窄栏 + 抽屉 | 视频/素材列表默认收起，未选中视频时自动展开，选中后收起；M 键切换。只改变显示，不改变选择或编辑状态 |
| 中间画布 | 占据其余全部空间；工具条、缩放、小地图（A）等浮在画布上；告警浮在画布上方，不挤压画面 |
| 底栏 | A/B 使用帧条（空间足够时每帧一格；最多 240 格，窄窗口按可用宽度合并区间）+ 上一/下一/播放/跳帧；C 使用修改项导航。浏览不提交、不选择 |
| 右侧检查面板 | A 追踪/暂停核对与本帧对象，B 提交本帧与对象，C 确认本项与修改项列表；可收起，A 普通模式暂停时强制展开；A 专注时改为图下紧凑核对条与按需检查侧区；B/C 专注时保留 |

- 新增功能先确定属于哪个区域；不要再增加常驻整行。页面只样式化自己的内容，外壳的列宽、抽屉、专注与断点只在 `shell.css`。
- 主题颜色走 `style.css` 变量；Chrome 93 不支持 `color-mix`，用 `--a-soft/--a-line/--b-soft/--b-line` 等显式变量。
- 各区域仍遵守以下职责，不能因收起或移动面板改变业务状态。

| 固定区域 | 职责与约束 |
| --- | --- |
| 顶栏上下文 | 阶段、帮助、视频身份、真实状态、阶段完成入口；B/C 展示各自的真实提交/确认进度。人工标注显示当前帧及含标注帧数，不能伪造“完成百分比”，全视频覆盖在送审时校验 |
| 左侧视频抽屉 | 切换素材/任务；未选中时展开、选中后收起，只改变显示，不改变编辑和选择 |
| 中间主图 | 三页以完整帧为主要视野；C 在同屏旁侧保留同裁剪 A/B 局部图，用于比较当前对象。优先留给图像，不堆常驻表格 |
| 主图下方 | A/B 使用帧导航，C 使用修改项导航；按钮明确写出导航单位，浏览不产生提交或决定 |
| 右上主操作 | A 的 AI 追踪（暂停时改为暂停核对）、B 的提交本帧、C 的确认本项；保存/失败/重试就近显示，不能被长列表挤出首屏 |
| 右下对象或修改项 | 一份列表承担选择和定位；A 提供对象操作，B 默认展示全部已有框，C 按帧分组展示净修改项；只滚动列表或次要区域 |
| 按需详情 | A 的位置尺寸、B 的对象对比详情默认折叠；C 的判断依据是完整帧与 A/B 图像，不展示几何指标。展开、筛选和选择不能跳动整个页面 |

- 共用 `WorkbenchShell.vue` 和 `workbench/shell.css`；列宽、抽屉、检查面板折叠与窗口高度由共享层管理，页面样式只处理内部内容。检查面板的收起偏好按页面保存；不要为某页复制另一套侧栏和断点规则。旧 `WorkbenchHeader` / `WorkbenchLayout` / `WorkflowProgress` 不再作为三页布局入口。
- 使用本地字体与共享浅深主题变量；常读文字 13 px、辅助 12 px、细节最低 11 px。主按钮用 `--on-accent` 保证两主题可读，A/B/选中颜色语义不变。页面样式必须限制在自身根类内，不能让通用按钮、列表或徽章覆盖其他页。
- ≤960 px 时视频列表以覆盖式抽屉打开，选中或收起后让出画面；检查面板移到画面与导航下方，允许页面滚动，列表保留内部滚动。C 在 ≤960 px 时完整帧在上、A/B 局部图在下。响应式只改变排列，不改变选中对象、真实帧、草稿或确认状态；专注布局优先于所有断点。
- 新功能先确定用户要完成的动作，再放入对应区域。统一布局不要求每页展示相同数据；不能只因后台有指标就给使用者增加详情入口。能够由对象列表或必要详情表达的信息，不再新增一张重复常驻卡片；移除入口时同步清理重复导航和说明。
- 三页共用观看交互：`+`/`=`、`-`、`0` 放大/缩小/适应，Ctrl/⌘+滚轮以指针为锚缩放，Space+拖动/中键平移，H显隐，F专注，G聚焦跳转输入，?帮助。A/B 的 K 播放、方向键逐帧；C 的方向键逐修改项、A/B键即时选择、撤销决定语义保留。B 的 G 替代旧 F 跳帧，K 替代旧 Space 播放；不可再让同一个观看键执行不同业务。只读或保存待重试时仍可纯观看，输入/组合输入/帮助及提交导出弹窗隔离，Space按钮激活和C框键盘选择保留。平移必须先于框/角点编辑捕获，失焦/切页/弹窗时复位；观看不得改变几何/提交/决定。手动缩放禁自动适应复位；C完整帧与A/B局部倍率独立。B/C专注占满浏览器窗口且保留右侧核心操作，显隐/专注/缩放不卸载业务工作区。
- 保持 A 紫色、B/AI 绿色、选中金色及浅深主题语义。已调整/未调整是几何状态，不能用来暗示已审查；B 仍逐帧显式提交。C 改变筛选不清掉当前比较项，可用“定位当前项”回到其列表位置。
- 专注模式是人工标注的全窗口变体，保留编辑、追踪、异常确认、保存和帮助；未暂停时退出恢复原视图，暂停修框时切换保留当前渲染倍率和所选对象。不能让记住的侧栏收起状态破坏全宽全高。异常对象入口选中并将框带入可见画布，保留用户缩放；单对象正常与整帧全部正常明确分开，只有服务端确认所有待处理项保存成功才续追。
- A 暂停时优先保证可修框的图像区域：普通模式在右上 AI 区核对，专注模式在图下保留紧凑的对象与确认操作条。两种模式固定使用“本对象无异常”“已修正本对象”，最后一项不改名；仍须全部待处理项保存成功才续追。完整原因、参照与学习选项放入按需侧区并独立滚动，已保存正常确认保留独立折叠入口，不能覆盖图像或向上压缩画布。专注只打开精简检查侧栏，不恢复整套素材库和对象侧栏；窄屏仍可收起详情。展开/关闭不重新适应倍率、不切换选中对象、不抢走编辑焦点，拖框不自动改变面板状态；目标可见则不平移，侧栏变窄后框被裁出视野才最小平移，主动对象定位遵循同一规则。检查侧栏内 Esc 或“收起检查依据”关闭详情并恢复入口焦点，其他位置 Esc 保留原行为。最后一个待处理项保留定位入口。返回暂停帧、补缺框、回退重追、保存失败和对应重试仍直接可用，不能藏在说明中。窄屏及短高窗口通过区域或页面滚动容纳内容，不把画布压成窄条；布局不改变异常判断、确认范围、续追门槛或原请求重试语义。
- 检查侧栏按“当前对象 → 判断数据 → 参考与检查帧 → 确认范围”分层，使用信息卡与已有指标的数值/界限对照，避免把全部诊断及说明串成大段正文。当前对象优先，其他对象的依据需可辨认；数据缺失按原有证据显示，不补造数值、置信度或新判断。详情排版不重新计算异常、不改变反馈范围或运动学习资格。
- 变更后至少检查 1366×768、1180×760 的浅深主题及 760/390 px 窄窗口、长列表内部滚动、关键操作首屏可见和弹窗快捷键隔离，并回归受影响业务。规则不能替代异常态、空态、只读态与失败待重试的验证。

## A：送审与完整性

送审前保存当前媒体工作区。服务端合并人工修正、Tracking、删除规则；提供 `sourceRevision` 与有框/明确空帧/未知帧统计。未知帧必须补标，或由用户明确声明为空，不能按“没有框”自动补空。带旧来源版本的完成请求应失败，不能固定混合版本。

送审者必须与已保存工作区的 `updatedBy` 一致。固定 A 包括视频全部 `0…N−1` 帧、稳定对象身份、类别、原始尺寸及来源内容摘要；相同作者、媒体与快照重复送审复用任务。A 永久保留，后续 B/C 不回写人工 seed、Tracking 文件或 A。

## B：帧状态与视频状态

送审者仅在审查任务尚未被领取/编辑时可撤回；领取即视为审查开始。撤回使用版本校验、幂等回执和 SQL 事务，将任务置 `withdrawn`，保留不可变 A 与人工工作区。任务不能再领取；再次送审创建新 A/任务，即使几何相同也不复用已撤回任务。送审状态与撤回入口持续可见，权限不满足时显示原因，审查列表的独立撤回不触发领取。已有视频及标注自动加载，人工文件夹“加载标注”入口已移除。

当前审查员可对仍在审查的任务执行“退回重新标注”，必须填写原因，使用版本/幂等校验与同一 SQL 事务，旧任务置 `returned_to_annotation` 并只读。原始 A、草稿、帧提交及人工工作区保留；该任务不再阻断原人工工作区修改/追踪/重新送审。重送生成新 A/任务，即使快照相同也不复用退回任务。已完成 B/C 不提供此直接回退，沿用本帧重审。此操作不同于送审者未领取前的撤回，也不同于 C 退回本帧重审。若 B 在本帧重审期间转为整段退回人工，旧 C 明确显示整段返工并保留只读记录，不继续等待已关闭的 B 产生新确认。

B 每帧净差量支持 update/add/delete，基于稳定 objectId 比较集合；新增后删除、删除后恢复 A 均为零净变化。删框只影响当前帧，A、seed、Tracking 文件均不改写。被删除对象保留恢复入口；补标可关联本视频既有对象或服务端保留的新编号，任何帧不能重复身份；新对象默认继承视频唯一类别，多类别必须选已有类别，空 A 默认 rare sperm，防止同一目标被拆成多个训练类别。对象分配与原键回执同事务，失败/响应丢失不能重复分配。存在性变化不计算 IoU/位移等不存在的几何指标。

重复导入按原视频 SHA-256 识别。取消不新增目录或素材；覆盖清空活动人工/AI/删除/校准/撤销记录并回到 0 帧，原视频内容及历史 A 保留。存在未撤回且未退回人工的送审任务时拒绝：未领取要求先撤回，已领取或后续状态禁止覆盖。服务端在修改前重新校验任务、工作区版本及 AI 运行状态。

| 操作 | 帧结果 | 对进度的影响 |
| --- | --- | --- |
| 浏览、跳帧、播放、选框 | 仅改变浏览位置/选择 | 无 |
| 第一次改框并保存 | `draft` | 不计提交 |
| 显式提交成功（含空帧、无修改帧） | `submitted`，保存不可变 submission | 增加 |
| 已提交帧再次修改 | 新草稿，保留上次有效提交引用 | 从已提交数扣除 |
| 净差量恢复到上次提交（含存在性） | 恢复 `submitted` | 恢复原进度，不新增提交 |
| 放弃首次草稿 | A / `unreviewed` | 不增加 |
| 放弃已提交帧的新草稿 | 恢复上次成功 B 提交 | 恢复原进度 |
| 全部帧提交 | 视频仍 `in_progress` | 100%，等待显式完成 |
| 完成视频审查 | 视频 `reviewed`，固定完整 B | 新任务同时生成 F；历史任务生成 C 任务 |

视频状态为 `pending → in_progress → reviewed`。领取/编辑依据服务器返回的 `permissions`，已完成或来源不完整的历史任务只读。提交成功自动进入下一个未提交帧；完成按钮必须额外确认，不能因为浏览/播放/保存草稿而完成。

B 完成事务只读取每帧当前有效 submission，净差量按 A 对比当前 B 计算。多次修改同一对象只生成一个最终 change。零修改视频也固定完整 B，并生成 0 changes 的 C 任务。

### 草稿、断点、失败

- 松手保存，一次手势一个撤销步骤；当前帧最多 50 步，切帧清空 B 撤销栈。
- 默认进入首个未提交帧；独立保存每个用户最后浏览帧，并提示上次位置及草稿。恢复草稿不计提交。
- 写入串行；失败保留本地框与原幂等键，不推进帧、不显示“已保存”、不直接离页。优先原请求重试；冲突可备份本地 patch，再明确重新读取。
- 成功落库的草稿可刷新恢复；尚未发送/成功的编辑不保证异常断电恢复。关闭或刷新时用未保存提示保护用户。

## C：逐项决定、恢复与最终版本

视频状态 `pending → in_progress → confirmed`。领取不产生决定；浏览不选择；点击 A/B 即保存；自动下一项可关闭。最后一项选择后显示完成确认弹窗，关闭弹窗仍保留顶部完成入口。

- 待选数只统计 B 净变化；未修改对象自动沿用 A。
- `decisionRevision` 控制每项并发；决定保存后才能更新进度。可重选、撤销上一次选择；撤销历史存服务端，刷新后有效。
- 游标与业务版本独立；重进恢复上次项，也可跳到首个待选项。
- 未确认保存的操作按账号写入 `sessionStorage`；网络超时、响应丢失、刷新、重新登录后可用原键重放。409 时不能静默覆盖，应明确读取服务器状态。存储不可用时提示/记录失败，不承诺意图恢复。
- 全选 100% 仍需显式完成；**零修改视频同样需要显式完成**。
- 完成事务生成 F 的全部帧，含未修改帧、空帧和每个对象的 A/B/决定来源。历史 A/B/F 和决定事件保留。
- “重新确认”保留选择与历史 F，重新开放编辑；再完成生成新 F，旧 F 仍可追溯，但不能据旧 F 导出训练集。

### 退回本帧重审

C 在当前修改项 A/B 均不合适时，可填写原因退回其所在整帧。只有当前领取人可操作，版本/幂等校验与状态变更同事务。旧 C 置 `returned`、只读；原 B 回到 `in_progress`，仅该帧取消有效提交，保留原 submission 与 B 几何供继续检查。原 A、固定 B/C/F 和决定事件不改写。该帧恢复原几何或放弃草稿均不能恢复提交，必须重新显式提交；其他帧仍按正常草稿规则处理。

B 重新提交并完成视频后固定新 B 和新 C，由原确认人继续。其他帧存在性、类别、几何均未变化且已有决定的项以带源事件关联的新决定继承；退回帧的修改项全部重新选择。补标项 A 无/B 有，删除项 A 有/B 无；C 可采用/拒绝存在性变化。未变化项/空帧仍按原完整帧规则固定；新 C 仍需显式完成，即使重审后没有修改项。旧 C 提供新任务入口，可多轮退回。重审及再次确认完成前，旧训练包停止下载；旧审计证据不改变。

## 指标与坐标

B/C 使用原图连续像素 `bbox=[x1,y1,x2,y2]`；B 草稿标准化到 0.001 px。已有对象类别继承 A；对象存在性由 B 净变化与 C 决定确定。补标关联全视频已有身份或服务端分配的新身份，不能按列表位置分配/复用编号。API 帧号 0 起，页面 1 起。缩放、平移和裁剪仅改变显示。

- IoU = 交集面积 / 并集面积；连续坐标不加 1。B 未修改对象显示 `—`。平均 IoU 如用于统计只能计算修改框，页面不常驻展示该汇总。
- 中心位移 = `sqrt(Δcx²+Δcy²)`；最大位移如用于统计只取当前帧修改框，页面以选中对象详情为主。
- 宽高变化 = `B.width−A.width`、`B.height−A.height`，保留正负号；C 数据中同时保留中心 ΔX/ΔY，但确认页面不展示这些指标。
- 指标表示改动幅度，不能判定谁更准确；不计算 Precision/Recall。
- A/B 局部对比必须使用同一原图裁剪范围；C 完整帧上下文不随局部缩放裁掉目标。

## 训练数据集准入与产物

新任务训练集入口在审查页已完成区域，直接使用审查接受的最新 F；历史任务仍在 C 已完成区域。默认 YOLO，支持 COCO / 双格式。必须同时满足 B `reviewed`、C `confirmed`、F 是当前确认任务最新版本且快照完整、原视频内容 SHA 一致。创建、发布、查询和下载都校验资格；旧 `POST /api/export/dataset` 返回 410，不能绕过。

重新确认期间暂停导出与旧训练包下载；再完成后只能使用新 F。用户已经下载的文件不会被远程撤回。

- 输出真实完整逐帧图像和标签；未修改对象来自 A，修改对象来自 C 选择。采用新增进入 F，确认删除及拒绝新增不进入 F 对象数组，所有不存在项的选择仍保存在独立决定记录/审计中。空帧保留，YOLO 对应空标签文件。禁止占位图、默认尺寸、漏帧或从原始工作区直接导出。
- YOLO 类别从 0 编号，按各视频实际宽高转为归一化中心 x/y/宽/高。ZIP 包含训练/验证图像与标签、`data.yaml`、追溯 manifest；详情以生成代码及测试为准。
- 默认 80/20 划分；至少两帧且有正样本。多视频 API 可用，当前 UI 只导出当前视频；连续帧随机划分不代表跨视频泛化验证。
- 任务 `queued → running → ready / failed`；资格失效返回 `invalidated`。创建幂等；响应丢失按原键恢复任务；重启时未完成任务标为失败，用户重新生成。
- 创建数据集任务的同一事务自动固定质量审计快照。前端沿用原导出按钮，无额外审计操作；训练包 manifest v2 为每张图片保存 sampleId、视频/帧/F 与审计摘要，对象旁表保留 YOLO 行号/COCO ID。完整人员和操作历史留在数据库，运维用 `export-audit.sh` 批量只读提取。重复导出次数与审查工作量分别统计。
- 当前不自动清理已完成包、不提供空间配额或跨进程任务队列。

## 核心验收边界

空帧/未知帧区分；自审、自确认允许且异账号已领取保护；草稿与提交分离；100% 与完成分离；A/B/F 不可变；原请求重放不重复写；失败事务整体回滚；断点恢复不增加进度；旧最终版本与旧接口不能导出训练集。对应脚本和故障注入见 [TESTING.md](TESTING.md)。
