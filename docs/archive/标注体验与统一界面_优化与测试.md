# 标注体验与统一界面：优化与测试

日期：2026-09-27

## 1. 本次范围

保留人工标注、SAM3 追踪、送审、B 逐帧审查、C 对比确认及最终训练数据集导出的业务规则。未修改追踪算法、模型配置、A/B/最终版本结构、审核权限或导出准入条件。

本次优化人工标注的布局、显示辅助、指针操作、快捷键、帧读取及保存反馈，并将登录、记录、审查、对比确认和导出弹窗适配到统一外观。

## 2. 页面定位与外观

主导航只表达三个操作阶段：**人工标注 → 审查模式 → 对比确认**。最终训练集仍在对比确认完成后导出。“自动入库”是系统行为，不再占用流程步骤。

原“标注结果”改名为**标注记录**，移至导航右侧的独立查询入口。它查询已经入库的人工新增 / 修改对象及标注人，不包含全部 AI 追踪结果，也不代表最终确认版本。因此无需经过此页即可送审。保留查询功能，增加对象 / 文件 / 标注人搜索和每页 50 条分页；界面按媒体 ID 区分同名文件，帧号统一从 1 显示。

默认浅色工作面板，使用蓝绿色主色、分层背景、统一边框、按钮与字体。视频 / 图像画布保持深色，让用户区分操作区和图像区。顶部可切换深色，偏好在本机保存；登录、人工标注、记录、B/C 及导出弹窗使用相同外观变量。

人工标注布局：

- 顶部：简短页面标题、保存状态、快捷键说明和“完成标注并送审”。
- 左侧：素材列表、搜索、导入视频 / 图片、加载已有标注。
- 中间：文件信息、常用工具、主画布、逐帧导航 / 时间轴、简短状态栏。
- 右侧：对象名称、可搜索的本帧对象、选中对象像素信息和 AI 追踪。
- 专注模式隐藏两侧面板，画布获得更多空间，退出后恢复原布局。

追踪异常仍保留完整提示、最近人工基准、建议检查范围、指标和处理建议，放在可展开详情中。直接继续追踪会将本帧异常框作为新人工基准的含义仍明确展示。

## 3. 标注显示与辅助操作

### 3.1 更清楚的框

- 普通框 2 屏幕像素，选中框 2.5 像素，并有暗色轮廓衬底。缩放图像时文字、框线与手柄保持可读尺寸。
- 人工框紫色虚线、AI 框绿色实线、选中框金色，与对比页 A/B 的视觉语言协调；框内仅保留很淡的选中提示，不遮挡目标。
- 名称有暗色描边，可单独关闭；全部标注可临时隐藏以查看原图。
- 四角手柄的命中半径使用屏幕像素，避免在高分辨率素材上出现过大的命中范围。
- 最小新框为 2 × 2 原图像素，取消旧版宽高必须超过图像 2% 的限制。移动 / 缩放仍受原图边界约束，保留小数坐标。

### 3.2 观察不同视频

- 相邻帧、前后 10 帧跳转、帧号输入、时间轴和播放速度选择。
- 指针位置缩放、适应画面、空格拖动平移和专注模式。
- 局部放大镜直接绘制源图像像素，带中心十字与原图位置。
- 亮度、对比度、暗场 / 低对比预设及反相显示，全部只改变预览，不改源文件、标签坐标或训练集。
- 横向、纵向素材保持原图宽高比，放大后的区域通过滚动 / 平移查看。

### 3.3 操作与恢复

- 指针移动只修改当前手势预览；松手后一次提交完整修改，原框在提交前进入撤销历史。
- `Esc` 或指针取消可放弃当前手势，不留下半次修改。单击选中不会把 AI 对象误改成人工对象。
- 撤销 / 重做按素材与帧隔离，每帧最多 50 次；当前帧撤销不回滚其他帧，也不改其他帧的删除标记。历史保留在当前页面会话中，不承诺刷新后恢复历史栈。
- “复制上一帧”只补充当前帧缺少的对象身份，已有对象不会被覆盖或重复添加，复制可撤销。
- 记住上次选中的视频，重新打开时恢复服务端保存的帧位置与标注。
- 播放、读取精确帧、恢复工作区或 AI 运行时暂停编辑，避免用户对未对应的帧写入标注。

## 5. 流畅度与保存处理

1. 原实现每次拖动都会遍历并替换全视频标注数组、触发深层监听。本次只在松手后提交一次；指针预览按浏览器动画帧合并更新。
2. 按帧建立对象索引，普通切帧从索引取对象，不重复扫描整个视频。
3. 精确帧 Blob 使用 LRU 缓存，最多 12 帧、32 MiB，超限淘汰。并发相同帧合并请求，相邻帧预读。切换素材清空缓存，失败请求不缓存。
4. 先解码图像，再同时切换帧号和图像；过时请求不能覆盖新的目标帧。读取失败保留此前对应帧并锁定编辑，重试读取失败的目标帧。
5. 切帧不再反复下载整份 Tracking 结果；结果在打开素材和已有追踪更新节点加载。浏览器检查确认反复切帧不会增加整份结果请求，缓存命中不会增加帧下载请求。
6. 同一媒体的工作区写入串行执行，避免旧请求晚完成覆盖新状态。切换媒体后旧保存保留该媒体自己的显示位置；重新进入时等待其未完成保存后恢复。
7. 保存状态明确区分保存中、已保存与失败；失败可重试，失败的服务端保存不会被显示为已保存。切换页面前保存当前工作区，失败则留在当前页。
8. 帧读取超时 20 秒，Tracking / 工作区 JSON 请求超时 30 秒，避免断线后无限等待。浏览器关闭 / 刷新时若服务端保存尚未完成或失败，触发未保存提示。

缓存和预读改善重复浏览及相邻帧切换；首次提帧仍受视频解码、图像大小、网络和后端负载影响。AVI 等浏览器不支持直接播放的视频继续使用既有逐帧播放回退，速度可能低于原始帧率。本次没有优化 GPU 模型推理，也未运行真实 GPU 追踪任务。

## 6. 日志与排查

客户端浏览器控制台记录：

- `annotation.frame_slow`：超过 250 ms 的帧读取，包含媒体、帧号和耗时。
- `annotation.frame_failed / prefetch_failed`：精确帧失败和预读失败。
- `annotation.workspace_save_failed`：媒体、保存序号和错误。
- `annotation.local_save_failed / selection_save_failed`：本机缓存与偏好写入异常。
- `annotation.tracking_load_failed`：整份追踪结果读取异常。
- `records.load_failed`、`ui.preference_save_failed`：记录页与外观偏好异常。

排查顺序为页面错误 → 浏览器对应事件与请求 → 服务端访问日志及既有审查日志。未增加持续鼠标移动日志，避免日志量影响操作。失败注入脚本另保存控制台输出，不输出认证令牌。

实际验证中，依据请求日志修正了测试夹具的 JSONL 格式；依据控制台中的开发服务器热更新记录修正测试获取工作区实例的方式。既有契约测试指出异常详情中的重要提示缺失，已恢复相应信息，没有删除这些回归断言。跨帧撤销增加了独立回归，防止其他帧删除标记被恢复。还将用户切帧锁定与任务内部定位分开，使用模拟完成 / 暂停响应确认 AI 任务结束后仍能跳到正确帧。
