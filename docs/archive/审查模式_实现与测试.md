# 审查模式实现与测试交接

日期：2026-09-26

> 后续更新：2026-09-27 已实现独立的 C 对比确认流程，详见 [对比确认实现与测试](对比确认_实现与测试.md)。本文保留 B 阶段交付时的范围及测试记录。

## 1. 本次实现范围

本次实现现有 Vue / FastAPI 项目中的审查模式 B，以及让 B 可以接收真实标注结果的必要送审入口。保持现有标注编辑、Tracking 算法和 C 页面；顺带修复现有最终版本列表接口的同名函数递归错误。B 完成时向现有 C 数据表交付固定版本和净变化对象。本次没有重做 C 的权限、裁决页面、最终版本导出等完整流程。

已实现的页面区域：流程导航；可搜索、筛选的视频任务列表；真实视频帧与已有框编辑；帧统计与提交操作；A/B 使用同一裁剪范围的真实局部对比；对象对比表与视频进度。

B 只能移动或缩放已有框。原始 A 永久保留；不提供新增、删除、类别修改、问题标记、Precision/Recall。未修改对象 IoU 显示 `—`；修改对象统计连续像素坐标下的 IoU、中心位移和宽高变化。坐标内部采用原图 xyxy，显示为 x/y/w/h；保留 0.001 px 精度。

页面支持适应窗口、缩放后滚动、选中对象定位、逐帧播放预览、帧号跳转、时间轴、撤销、快捷键及弹窗焦点管理。播放逐帧解码真实图像，速度受图像请求和解码时间影响。

## 2. 使用步骤

1. 按项目原有方式启动后端和前端。已运行旧后端时需要重启后端，并刷新前端，保证两端使用同一版本。
2. A 在人工标注页加载视频，完成标注和 Tracking，点击底部的 **完成标注并送审**。
3. 系统先保存当前工作区，再从后端合并人工修正、Tracking 和删除规则。预览显示对象帧、明确空帧、未知帧。未知帧不能自动补空：确认为空的帧由 A 填写帧号范围，其余须先补齐标注。
4. A 明确确认完成后，事务中生成全部视频帧的 A 快照和待审查任务。相同作者、媒体和快照重复送审会复用已有任务。
5. 使用当前账号或其他审查员账号进入审查模式，点击任务领取。允许标注员检查自己的标注。默认进入最早未提交帧，并单独提示上次浏览位置及其他草稿。
6. 每帧检查后点击 **提交本帧**。未修改帧、空帧也必须提交。提交成功自动进入下一个未提交帧。
7. 全部帧提交后仍处于审查中。B 再点击 **完成视频审查 → 确认完成视频审查**，固定 B 并生成 C 待确认任务。完成后允许浏览、选择和对比，禁止编辑。

本项目现有账号模型没有独立 reviewer/admin 角色。本次沿用单工作组账号，服务器按任务领取人控制编辑权限；送审者必须是已保存工作区的 `updatedBy`。允许 A 领取并审查自己的标注，无需设置环境变量；原 `REVIEW_ALLOW_SELF` 开关不再生效。已由其他账号领取的任务仍不能抢占或修改，完成后的版本仍只读。自审同样保留原始 A 和独立的 B 修改结果。

## 3. 状态与保存规则

| 行为 | 帧状态 / 数据 | 进度 |
|---|---|---|
| 浏览、跳帧、播放 | 只更新该用户的浏览游标 | 不增加 |
| 首次修改自动保存 | `draft`，独立于提交快照 | 不增加 |
| 提交成功 | `submitted`，新增不可变提交内容 | 增加 |
| 已提交帧再次修改 | 保留原 submission 引用，形成草稿 | 从已提交进度扣除 |
| 修改后回到上次提交几何 | 恢复 `submitted`，不新增提交记录 | 恢复 |
| 放弃首次草稿 | 恢复 A，`unreviewed` | 不增加 |
| 放弃已提交帧的新草稿 | 恢复上次成功提交的 B | 恢复 |
| 最后一帧提交 | 视频仍为 `in_progress` | 100%，可手动完成 |
| 手动完成视频 | 固定 B 所有帧，写入净变化及 C 任务 | 视频 `reviewed` |

拖动结束后立即保存；一次拖动对应一个撤销步骤，当前帧最多保留 50 步。切帧清空本帧撤销栈。保存中串行化写入；未知结果保存同一个幂等键用于重试。失败后保留本地几何，不显示成功、不推进帧、不允许路由直接离开。处理冲突时可先导出本地 patch，再明确选择读取服务端结果。

服务端草稿成功保存后可以刷新恢复。尚未发送成功的本地编辑不会伪装为服务端草稿；关闭/刷新前会触发浏览器离页提示。异常断电前尚未落库的编辑不承诺恢复。

快捷键：`←/→` 浏览帧；`[/]` 选择框、不循环；`F` 定位帧号输入框；输入框内 `Enter` 跳转；`O` 叠加原框；`Ctrl/⌘+Z` 撤销；`Ctrl/⌘+Enter` 提交；`Space` 播放/暂停；`?` 帮助；`Esc` 取消拖动、关闭弹窗或取消选择。文本输入、IME、长按重复事件与普通快捷键隔离。视频完成没有快捷键。

## 4. 数据与接口

新增模块：

- `backend/app/review_workflow.py`：草稿、提交、放弃、领取、游标、完成、幂等事务及增量迁移。
- `backend/app/review_workflow_routes.py`：实际注册的审查 API、认证和结构校验、请求号。
- `backend/app/annotation_completion.py`：已保存 A 来源汇总、覆盖校验和冻结入口。
- `backend/app/review_source_lock.py`：来源读取与写入锁，沿用项目既有单后端进程部署约束。
- `backend/app/review_logging.py`：审查专用滚动日志。
- `frontend/src/pages/ReviewPage.vue`、`frontend/src/review/`：审查页面和几何逻辑。
- `frontend/src/components/SendToReview.vue`：标注页送审入口。

新增表：`review_submission_payloads` 保存不可变提交 patch；`review_version_frames` 固定完整 B；`review_write_receipts` 保证业务写入及响应幂等；`review_bookmarks` 保存每个用户的浏览位置和独立版本号。复用现有 A、B、C 主表和用户表。

写入统一使用 `X-Review-Contract: 2`、`Idempotency-Key` 及明确的期望版本字段。草稿、提交、放弃使用 `expectedFrameRevision`；视频完成使用 `expectedSessionRevision`；游标使用 `expectedCursorRevision`。幂等重放先于版本校验，事务中同时保存业务变化和成功响应。SQLite 外键始终开启。

当前实际送审接口为 `GET /api/review/media/{mediaId}/completion-preview` 与 `POST /api/review/media/{mediaId}/complete`。旧客户端上传任意 frames 冻结 A 的入口已停止注册。B 页面不再根据接口错误构造 10 帧空数据。

B 接口：`/sessions`、`/sessions/{id}`、`/claim`、`/frames/{index}`、`/frames/{index}/draft`、`/submit`、`/discard`、`/sessions/{id}/freeze`、`/cursors`。帧号 API 从 0 开始，用户界面从 1 开始。

B 完成事务只引用每帧当前有效 submission，写入固定帧和 A/B 净变化。已修改多次的对象只产生一个最终变化，不混入旧提交或未提交草稿。无变化视频仍生成完整 B 与 0 changes 的 C 任务，C 后续处理属于现有确认流程。

## 5. 旧任务与数据保护

启动时增量建表，保留旧表和旧数据。仅能从旧任务当前已提交帧重建对应提交快照；不能恢复的历史内容不编造。

本次只读检查发现当前数据库两个旧任务的 A 均只有 10 帧，实际视频分别为 12 帧和 678 帧。这些任务在新页面会显示只读原因。需要由 A 重新加载真实标注、检查全视频后送审；旧任务保留，不自动补帧或迁移成“已完成”。

已被 A 快照引用的原视频禁止通过素材删除接口删除。来源冻结与保存/Tracking 发布互斥，并校验来源摘要。继续采用现有部署文档规定的单 worker 后端；本次没有实现跨进程文件锁或多租户权限系统。

开发与自动化测试使用 `work/` 内独立数据库、生成视频和独立端口。没有向当前真实业务数据库写入测试标注。

## 6. 日志与排错

默认日志：`backend/data/logs/review.log`。设置 `APP_DATA_DIR` 时位于 `$APP_DATA_DIR/logs/review.log`。单文件 5 MB，保留 5 个历史文件。

- `review.request`：请求号、HTTP 方法、接口、状态。
- `review.committed`：动作、任务、帧、操作者、幂等键。
- `review.replay`：原成功结果重放。
- `review.rejected`：业务错误码、任务、帧和幂等键。
- `review.storage_failed` / `review.request_failed`：异常堆栈。
- `annotation.completed`：送审媒体、创建或复用任务、操作者。

页面服务端错误显示 `req_...` 记录号，可在日志中搜索定位。浏览器另有 `review.request_failed`、`review.operation_failed`、`review.cursor_failed` 等控制台记录。日志不输出密码或 JWT。

本次依据请求日志定位并修复了“JSON 字段顺序造成假 dirty、重复保存和重复提交按钮启用”的问题；故障测试同时确认了失败写入的事务回滚、响应丢失后幂等重放和 409 冲突保留本地修改。
