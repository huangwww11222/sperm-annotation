## 2. 使用流程与页面

1. B 逐帧提交并明确完成视频审查后，自动生成 C 任务。
2. 打开“对比确认”，从左侧搜索、按待确认 / 确认中 / 已确认筛选视频。卡片展示修改项进度，媒体标识和任务尾号帮助区分同名视频。
3. 未分配任务需点击“领取并开始确认”。允许原标注员或审查员用同一账号确认自己的工作；已由其他账号领取的任务允许查看，不允许抢占。
4. 中间展示当前帧、对象编号和修改项序号。并排 / 叠加视图共用同一原图裁剪范围，缩放为 3–8，默认 5。大幅变化时裁剪范围至少包含 A、B 两个完整框，避免把框裁掉。
5. 下方始终保留完整帧上下文，其他对象淡显。当前帧修改项表、逐项队列、上一项 / 下一项、序号跳转和“首个待确认”可以切换对象。队列每组展示 50 项，全部项目都可通过序号和前后导航到达。
6. A/B 位置、尺寸、IoU、中心位移、中心坐标差和宽高变化使用原图像素。IoU 采用连续矩形交并比，不加 `+1` 像素。修改类型按中心是否移动、尺寸是否改变分类。指标仅表示变化幅度，不判断标注质量。
7. 点击保留 A 或采用 B 即保存。服务器确认成功后更新计数；默认跳到下一待确认项，可取消自动跳转。选择相同值不会新增事件。已有选择可再次更改。
8. 所有修改项选择完毕会提示完成，但必须明确点击“确认完成”才生成最终版本。没有修改项的视频也需领取并明确完成。
9. 完成后只读，可继续查看修改项并导出完整视频 JSON。选择“重新确认”后保留既有选择、恢复编辑；再次完成产生新的最终版本，旧版本仍保留。

本页面只对 B 的净修改项逐项选择。未修改对象直接沿用 A，不需要重新逐帧确认。

## 3. 状态与恢复

| 层级 | 状态 | 转换 |
| --- | --- | --- |
| 修改项 | 待选择 | 初始状态；撤销第一次选择后恢复 |
| 修改项 | 保留 A / 采用 B | 保存成功后进入；再次选择可替换 |
| 视频 | `pending` | 创建或领取；浏览和领取不计入确认进度 |
| 视频 | `in_progress` | 第一次选择、撤销或重新确认；即使全部已选择也不会自动完成 |
| 视频 | `confirmed` | 全部选择后明确完成；当前结果只读 |

撤销按本视频的选择记录逆序进行。撤销第一次选择恢复待选择，撤销 A/B 切换恢复此前的选择；返回受影响对象。撤销追加补偿事件，保留原事件，刷新后仍可连续撤销。浏览、切换显示方式、领取、保存游标不进入选择撤销栈。

服务器按账号和任务保存最后浏览位置，另行提供首个待确认项。二者不同会提示“留在上次位置”或“从首个待确认开始”。已保存选择与撤销记录以服务器为准；本地仅保存显示偏好和最近打开任务。

与 B 的几何草稿不同，C 没有额外的“提交本项”或未提交选择草稿：每次 A/B 选择都是即时写入。对于断网、超时或响应丢失，客户端保留原操作和幂等键，在同标签页的 `sessionStorage` 中按账号备份，支持刷新后重试。不把未确认写入显示成已保存，不提前推进。

未决操作存在时，路由离开先尝试原请求，仍失败则留在页面；刷新 / 关闭有浏览器提示。用户可备份未决操作 JSON，再明确选择采用服务器结果。登录失效时提供保留操作并重新登录入口；同账号重新进入页面可继续原请求。浏览器禁用存储或彻底关闭标签页时，不承诺恢复未落库操作；服务端成功写入的选择不受影响。

## 4. 快捷键

| 按键 | 行为 |
| --- | --- |
| `A` / `B` | 保留 A / 采用 B，立即保存；自动推进由勾选项控制 |
| `←` / `→` | 上一 / 下一修改项，不产生选择，到端点停止 |
| `Ctrl+Z` / `⌘Z` | 撤销本视频上一次选择并返回该项 |
| `?` | 打开快捷键说明 |
| `Esc` | 关闭当前对话框 |
| `Tab` / `Shift+Tab` | 对话框内焦点循环 |
| 序号输入框中的 `Enter` | 跳转到输入的修改项 |

输入框、文本区、可编辑区域、IME 组合输入、长按重复事件与业务快捷键隔离。Ctrl / ⌘ / Alt 组合不会误触 A/B；只读、加载或写入中、未决操作待处理时不能选择。弹窗打开时不触发业务快捷键。视频完成没有快捷键。

## 5. 数据结构与流向

```text
不可变 A 的 baseline_frames
          +
B 完成时的 review_version_frames + review_changes
          ↓
C 逐项选择事件 decision_events
          ↓
当前有效选择 decision_heads + 每项版本 confirmation_change_versions
          ↓ 明确完成，单个数据库事务
final_versions
  + final_version_frames（全部帧，含空帧）
  + confirmation_final_records（选择快照与前一最终版本）
          ↓
完整视频 JSON
```

新增 `confirmation_actions` 保存选择前后值与撤销关联；`confirmation_bookmarks` 保存个人游标及独立版本；`confirmation_reopen_events` 记录重新开放确认。复用 `review_write_receipts`，请求摘要以 `confirmation` 区分 B/C。原有 `final_frame_objects` 同时写入以保持旧读取方的兼容性，新 JSON 导出以完整帧快照为准。

最终 JSON 包含媒体尺寸、帧率、全部帧数、A/B 版本、确认人、确认时间、快照摘要和前一最终版本。每个对象包含 `objectId`、`annotationId`、`classKey`、最终 `bbox`、`baselineBBox`、`reviewBBox`、`choice`、`resolution`、`changeId` 和 `decisionEventId`。未修改对象的 `choice` 为 `null`、`resolution` 为 `unchanged`；其最终几何来自 A。空帧的 `objects` 是空数组。

坐标为原图 `bbox=[x1,y1,x2,y2]`，保留已有小数精度；API 帧号从 0 开始，页面从 1 开始。完成事务检查对象集合、类别、修改项引用和 A/B 几何一致性，禁止用不完整快照生成最终版本。

## 6. API 与并发控制

所有以下接口要求登录。写入还要求 `X-Review-Contract: 2` 和 `Idempotency-Key`。

| 方法与路径 | 作用 / 期望版本 |
| --- | --- |
| `GET /api/confirmation/sessions` | 列表 |
| `GET /api/confirmation/sessions/{id}` | 状态、权限、进度、恢复位置 |
| `GET /api/confirmation/sessions/{id}/changes` | 净修改项、当前选择和每项版本 |
| `GET /api/confirmation/sessions/{id}/frames/{index}` | 固定 A/B 完整帧标注 |
| `POST /api/confirmation/sessions/{id}/claim` | 原子领取 |
| `PUT /api/confirmation/sessions/{id}/changes/{changeId}/decision` | `choice`、`expectedDecisionRevision` |
| `POST /api/confirmation/sessions/{id}/undo` | `actionId`、`expectedSessionRevision` |
| `POST /api/confirmation/sessions/{id}/finalize` | `expectedSessionRevision` |
| `POST /api/confirmation/sessions/{id}/reopen` | `expectedSessionRevision` |
| `PUT /api/confirmation/sessions/{id}/cursor` | `changeId`、`expectedCursorRevision` |
| `GET /api/final-versions/{id}` | 完整最终版本 JSON |
| `GET /api/final-versions/{id}/download` | 相同完整 JSON 的附件下载 |

写入使用 SQLite `BEGIN IMMEDIATE`、期望版本检查和事务内成功回执。幂等重放先于版本检查；业务数据与回执同时提交或同时回滚。不同窗口对同一对象的过期写入返回 409，客户端保留意图，需明确读取当前结果后重新选择。游标版本独立，不改变业务版本；游标冲突可读取新游标版本后重试当前浏览位置。

旧版不带版本与幂等键的 C 客户端无法绕过约束。API 不接受 C 上传任意框坐标、类别、新增或删除对象。

## 7. 日志与实际排查

日志位于 `$APP_DATA_DIR/logs/review.log`；未设置时为 `backend/data/logs/review.log`。单文件约 5 MB，保留 5 个历史文件。

- `review.request`：请求号、方法、路径、状态和幂等键，可与业务记录对应。
- `confirmation.committed` / `confirmation.replay`：动作、任务、修改项、操作者和幂等键。
- `confirmation.rejected`：业务错误码、任务、操作者和幂等键。
- `confirmation.storage_failed`：数据库异常堆栈；事务回滚。
- `confirmation.export`：最终版本和导出操作者。
- 浏览器 `confirmation.request_failed` / `confirmation.operation_failed`：对应 API、任务、对象、状态、错误码和请求号。

日志不记录 JWT 或密码。页面服务端错误展示 `req_...`，可先用 `rg 'req_实际记录号' 日志路径` 定位，再按幂等键查完整操作。浏览器注入的模拟 503/401 不会进入后端，因此另有浏览器控制台记录；实际数据库故障通过测试中的 SQLite 触发器注入并验证异常日志。

开发中依据构建日志修复 Blob 泛型返回值的类型错误；依据重新登录后的截图、浏览器和请求日志确认操作已恢复，但页面初始化尚未结束，补充初始化阻塞状态，避免在恢复意图之前允许交互。并发冲突、响应丢失后的重放与数据库回滚均从响应和日志验证。

## 9. 启用与兼容边界

重启后端并刷新前端。启动时增量创建新表；不删除旧表、不改写原始 A/B。完成了当前 B 工作流的任务可直接进入 C。

缺少完整固定 A/B 快照的旧任务显示只读原因，不能猜测补帧或生成最终版本，需补齐来源后重新送审。旧最终版本若没有完整帧快照，新 JSON 接口明确拒绝导出；不以缺帧数据伪装完整结果。

初次交付的导出为包含完整视频的 JSON。后续已接入受审查与确认状态约束的 YOLO / COCO 训练数据包，并关闭原始标注导出的旧接口，详见上述迁移文档。GPU 推理不属于本次修改或测试范围；继续使用项目既有的单后端 worker 部署方式。
