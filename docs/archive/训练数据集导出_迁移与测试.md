# 训练数据集导出：迁移与测试交接

日期：2026-09-27

后续外观适配：[标注体验与统一界面优化](标注体验与统一界面_优化与测试.md)已将导出弹窗纳入统一浅 / 深主题，导出条件与数据格式保持不变。

## 1. 业务规则与页面入口

最终流程为：**人工标注 → 完成逐帧审查 → 完成对比确认 → 导出训练数据集**。

- 人工标注页面移除“导出训练数据集”入口，保留标注保存和送审功能。
- 对比确认页仅在视频明确完成确认、生成最终版本后显示“导出训练数据集”。全部修改项已有选择但尚未点击完成，仍不能导出。
- 允许同一账号标注、审查和确认自己的工作；沿用已有任务领取和写入权限规则。
- 导出弹窗使用项目统一的深色面板、按钮和字体。默认 YOLO，保留 COCO、YOLO + COCO 选项；默认训练 / 验证比例为 80% / 20%，可选 70% / 30%、90% / 10%。
- 弹窗展示全部帧、最终框、空帧、类别数，以及预计训练 / 验证帧数。生成时展示服务端进度和任务号，完成后下载 ZIP。
- 原“导出完整视频 JSON”保留作为标注与版本信息备份，与训练数据包分开。
- 点击“重新确认”后立即暂停训练集创建和已有训练包下载；再次完成生成新最终版本，只允许导出新版本。旧最终版本保留用于追溯。

这些限制在服务端执行，不能通过调用旧接口或直接提供原始标注绕过。

## 2. 导出内容与数据来源

导出请求只接受最终版本 ID、格式、划分比例，不接受前端传入框坐标或原始标注。

```text
A 原始快照 + B 完成审查时的固定版本
                       ↓
                 C 逐项 A/B 选择
                       ↓ 明确完成视频确认
           final_versions + final_version_frames
                       ↓ 校验状态、完整性和快照摘要
             原始视频提帧 + 最终框转换
                       ↓ 校验确认状态仍然有效
                  完整 ZIP 包发布
```

使用全部最终帧，不只导出 B 修改过的帧或框。保留未修改对象、已选择 A 的对象、已选择 B 的对象及空帧。原视频在提帧前后均核验 SHA-256，图像尺寸逐帧核验；视频缺失、内容变化、解码失败、尺寸不一致或写图失败都会终止任务，不静默跳帧，也不发布半成品。

YOLO 包示例：

```text
images/
  train/v000_frame_000000.jpg
  val/...
labels/
  train/v000_frame_000000.txt
  val/...
data.yaml
manifest.json
provenance/<finalVersionId>.json
README.md
```

- 图像为原始视频解码后的 JPEG，保留真实尺寸，不生成占位图。
- 每张图对应同名 TXT；每行 `class_id cx cy w h`。以实际图像宽高归一化到 0–1，保留 10 位小数；空帧对应空 TXT。
- 类别取最终快照的 `classKey`，排序后生成从 0 开始的统一映射。不将对象 ID 当作类别，不剥离 `CD4` 等合法类别名中的数字。
- `data.yaml` 包含 `train`、`val`、`nc`、`names`，不写服务端绝对目录。解压整个 ZIP 后，将该 YAML 的绝对路径传给 YOLO。
- `manifest.json` 保存实际划分、数量、来源视频摘要、媒体尺寸、A/B/C/最终版本引用和快照摘要；`provenance/` 保存全部帧及其 A/B/最终框、选择与来源。
- COCO 包使用 `annotations/instances_train.json` 和 `instances_val.json`，图片路径相对 JSON 文件；YOLO + COCO 同时生成两种标签，共用图像。

格式依据：[Ultralytics 检测数据集格式](https://docs.ultralytics.com/datasets/detect/)；省略 YAML `path` 时的目录解析依据：[Ultralytics 数据集读取实现](https://docs.ultralytics.com/reference/data/utils/)。

## 3. 划分与数据边界

按最终版本和帧号顺序进行确定性划分，训练 / 验证至少各一帧，同一图像不会同时进入两部分。训练集必须含目标；若至少有两张含目标的帧，必要时交换样本，让验证集也含目标，交换不改变两部分的帧数。实际划分记录在清单中。

至少需要两帧，且所选视频不能全部无目标。单帧视频或全空视频会返回明确原因。服务端支持合并多个已确认视频，统一类别映射并使用不同文件名前缀；拒绝将同一原视频的多个版本重复放入同一包。本次页面迁移的入口针对当前视频，尚无多视频批量选择界面。

同一视频中的相邻帧存在相关性，当前按帧划分适合先接通训练流程，不能据此声称具备独立视频评估效果。需要独立评估时，应按采集视频或批次组织训练与验证数据。

## 4. 异步任务与错误恢复

新增 `training_exports` 表记录操作者、幂等键、设置摘要、任务状态、进度、结果清单、错误码和时间。任务状态为 `queued → running → ready / failed`；查询时若确认已重新开放或版本已被替代，返回 `invalidated`。

- 后台提帧与打包使用单独工作线程，避免在一次 HTTP 请求中等待整个视频。
- 创建请求前，浏览器按“账号 + 最终版本”保存原设置和幂等键。响应丢失时用同一键重试，恢复同一任务，不重复创建。
- 关闭弹窗后服务器继续生成；刷新或重新进入该视频，打开导出弹窗可恢复查询和下载。切换视频会重新建立弹窗状态，避免串用其他视频的任务。
- 状态查询失败可重试；下载失败可以重试已有 ZIP，也可重新生成。错误显示请求记录号，任务区保留任务号。
- 生成中没有自动取消功能。服务重启将尚未完成的任务标为失败，需重新生成；已完成且确认仍有效的包仍可下载。
- 生成使用临时目录和 `.zip.partial`；最后再次校验状态，在数据库事务内发布完整 ZIP。正常成功或失败会清理临时文件。
- 下载接口要求登录、任务归属与当前确认状态同时有效；无法通过旧公开下载路径访问训练 ZIP。
- 浏览器禁用本地存储时会记录警告；服务端任务仍可执行，但不承诺刷新后的自动恢复。已经下载到用户电脑的文件无法通过之后的重新确认操作撤回。

沿用项目现有的单后端 worker 部署。后台队列不跨进程共享，不应直接扩为多个 worker；进程异常终止留下的临时目录需要运维清理。已完成 ZIP 暂无自动过期或空间配额策略。

## 5. 接口与日志

所有接口要求登录，创建还要求 `X-Review-Contract: 2` 与 `Idempotency-Key`。

| 接口 | 作用 |
| --- | --- |
| `POST /api/datasets/exports/preview` | 校验最终版本并汇总全部帧、框、空帧与类别 |
| `POST /api/datasets/exports` | 创建或幂等恢复导出任务 |
| `GET /api/datasets/exports/{id}` | 查询本人任务及当前有效状态 |
| `GET /api/datasets/exports/{id}/download` | 再次校验后下载完整 ZIP |
| `POST /api/export/dataset` | 旧入口返回 410 `FINAL_CONFIRMATION_REQUIRED` |

服务端日志沿用 `$APP_DATA_DIR/logs/review.log`，默认 `backend/data/logs/review.log`。

- `review.request`：请求号、接口、状态、幂等键。
- `dataset.queued / started / progress / ready / download`：任务号、数量与阶段。
- `dataset.replay`：原键重放及原任务号。
- `dataset.failed / enqueue_failed / interrupted`：错误码及异常堆栈或重启中断原因。
- 浏览器 `dataset.request_failed / operation_failed / restore_failed`：请求阶段、任务、错误与本地恢复情况。

排查顺序：用页面请求号定位请求日志，再用幂等键或 `train_...` 任务号查导出阶段和堆栈。日志不输出 JWT 或密码。模拟 HTTP 503 的浏览器测试仅在浏览器拦截，相关注入记录在控制台；真实服务端故障注入测试另行断言后端日志和回滚结果。

本次依据运行与构建日志解决测试环境缺少 YAML 依赖、启动事件注册方式不兼容、Vue 模板状态类型推断问题；切换视频的状态隔离问题增加了浏览器回归用例。
