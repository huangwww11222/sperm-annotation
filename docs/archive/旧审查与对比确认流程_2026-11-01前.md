# 旧审查与对比确认流程（2026-11-01 前）

2026-11-01 起删除了审查（B）与对比确认（C）页面及其接口，改为在同一工作台上直接纠错的审查，见 [WORKFLOW.md](../WORKFLOW.md)。下文从当时的 WORKFLOW.md 原样移出，仅用于理解服务器上保留的历史 A/B/C/F 数据；不是当前实现契约。

## 兼容的原三阶段流程与页面职责

```text
原视频 + 人工标注 + 已接受的 AI 追踪结果
  → 完成标注并送审：保存工作区、检查全帧覆盖、固定 A
  → B：修框/补标/删除本帧框 → 自动保存草稿 → 显式提交每帧
  → 全帧已提交 + 显式完成视频审查 → 固定完整 B 与净修改项
  → C：逐修改项保留 A / 采用 B → 即时保存决定
  → 全项已选择 + 显式完成视频确认 → 固定完整 F
  → 校验当前 F 与原视频 → 后台生成训练集 → 验证资格后下载
```

- **人工标注**：创建、删除、移动、缩放对象，逐帧检查，按当前帧 seed 进行 AI Tracking。
- **审查模式**：中间真实帧、缩放、播放、帧导航；右上撤销/提交和保存状态，右下本帧对象列表（全部/仅已调整/已删除/ID 搜索）。选中对象后按需展开同范围裁剪的 A/B 对比与几何详情，草稿入口也按需展开。允许移动、缩放、补标、删除本帧框及恢复；原 A 不改写，不改已有类别，不标记问题。常规增删无需填原因；整段返工可由当前审查员填写原因退回人工标注。
- **对比确认**：中间左侧为完整帧主图，旁边上下排列当前对象的 A/B 局部图，也可切换叠加，图下浏览上一/下一修改项。完整帧中金色外框只定位当前对象，A 紫色虚线/B 绿色实线对应旁边局部图；点击或用 Enter/Space 激活有修改的框，可同步切换局部图与右侧列表，不产生确认决定。完整帧可展开查看；页面不展示 IoU、位移和坐标等几何详情，指标仍保留在数据中用于追溯。右侧顺序为“确认本项”（A/B 选择、保存状态、撤销）→ 已完成时的训练集导出/重新确认 → 按帧分组的修改项列表，DOM 与视觉顺序一致。列表统一承担全视频导航和当前帧定位，支持全部/待确认/已确认、分页与定位当前项。处理 B 相对 A 的修框、补标和删除净变化，不生成第三种几何；A/B 任一侧可明确不存在对象。
- B/C **视频进度与完成按钮统一放在站点顶栏的工作区上下文中，专注时移到画布上方细栏**，B 展示真实提交进度，C 展示真实修改项选择进度；完整状态由任务与当前项数据提供。右上主操作与保存失败重试不随对象列表滚动。不能把正在浏览的帧号当已审查数量。
- **标注记录**：独立查询已入库人工新增/修改对象，按媒体身份区分同名文件，可搜索/分页。不是完整 AI 结果，不是 F，不是标注与审查之间必经步骤。
- **统计数据导出**：标注记录页的独立入口，导出全实例 A/B/C/F、人员和流程历史，包括未完成与历史版本，不受该页筛选影响。它是只读统计传输，不生成训练图片/标签，不修改视频完成状态，不绕过训练集准入。后台生成、本人查询/下载与原键恢复，不直接交付 app.db。
- **使用说明**：顶部入口打开对应页面章节，可搜索和下载完整说明。原生模态窗口隔离下层业务快捷键；关闭后恢复焦点和页面滚动。内容统一维护于 [用户手册](../frontend/src/help/user-guide.md)。

## A：送审与完整性

送审前保存当前媒体工作区。服务端合并人工修正、Tracking、删除规则；提供 `sourceRevision` 与有框/明确空帧/未知帧统计。未知帧必须补标，或由用户明确声明为空，不能按“没有框”自动补空。带旧来源版本的完成请求应失败，不能固定混合版本。

送审者必须与已保存工作区的 `updatedBy` 一致。固定 A 包括视频全部 `0…N−1` 帧、稳定对象身份、类别、原始尺寸及来源内容摘要；相同作者、媒体与快照重复送审复用任务。A 永久保留，后续 B/C 不回写人工 seed、Tracking 文件或 A。

## B：帧状态与视频状态

送审者仅在审查任务尚未被领取/编辑时可撤回；领取即视为审查开始。撤回使用版本校验、幂等回执和 SQL 事务，将任务置 `withdrawn`，保留不可变 A 与人工工作区。任务不能再领取；再次送审创建新 A/任务，即使几何相同也不复用已撤回任务。送审状态与撤回入口持续可见，权限不满足时显示原因，审查列表的独立撤回不触发领取。已有视频及标注自动加载，人工文件夹“加载标注”入口已移除。

当前审查员可对仍在审查的任务执行“退回重新标注”，必须填写原因，使用版本/幂等校验与同一 SQL 事务，旧任务置 `returned_to_annotation` 并只读。原始 A、草稿、帧提交及人工工作区保留；该任务不再阻断原人工工作区修改/追踪/重新送审。重送生成新 A/任务，即使快照相同也不复用退回任务。已完成 B/C 不提供此直接回退，沿用本帧重审。此操作不同于送审者未领取前的撤回，也不同于 C 退回本帧重审。若 B 在本帧重审期间转为整段退回人工，旧 C 明确显示整段返工并保留只读记录，不继续等待已关闭的 B 产生新确认。

B 每帧净差量支持 update/add/delete，基于稳定 objectId 比较集合；新增后删除、删除后恢复 A 均为零净变化。删框只影响当前帧，A、seed、Tracking 文件均不改写。被删除对象保留恢复入口；补标可关联本视频既有对象或服务端保留的新编号，任何帧不能重复身份；新对象默认继承视频唯一类别，多类别必须选已有类别，空 A 默认 rare sperm，防止同一目标被拆成多个训练类别。对象分配与原键回执同事务，失败/响应丢失不能重复分配。存在性变化不计算 IoU/位移等不存在的几何指标。

重复导入按原视频 SHA-256 识别。取消不新增目录或素材；覆盖清空活动人工/AI/删除/校准/撤销记录并回到 0 帧，原视频内容及历史 A 保留。存在未撤回且未退回人工的送审任务时拒绝：未领取要求先撤回，已领取或后续状态禁止覆盖。服务端在修改前重新校验任务、工作区版本及 AI 运行状态。

| 操作 | 帧结果 | 对进度的影响 |
| --- | --- | --- |
| 浏览、跳帧、播放、选框 | 仅改变浏览位置/选择 | 无 |
| 第一次改框并保存 | `draft` | 不计提交 |
| 显式提交成功（含空帧、无修改帧） | `submitted`，保存不可变 submission | 增加 |
| 已提交帧再次修改 | 新草稿，保留上次有效提交引用 | 从已提交数扣除 |
| 净差量恢复到上次提交（含存在性） | 恢复 `submitted` | 恢复原进度，不新增提交 |
| 放弃首次草稿 | A / `unreviewed` | 不增加 |
| 放弃已提交帧的新草稿 | 恢复上次成功 B 提交 | 恢复原进度 |
| 全部帧提交 | 视频仍 `in_progress` | 100%，等待显式完成 |
| 完成视频审查 | 视频 `reviewed`，固定完整 B | 新任务同时生成 F；历史任务生成 C 任务 |

视频状态为 `pending → in_progress → reviewed`。领取/编辑依据服务器返回的 `permissions`，已完成或来源不完整的历史任务只读。提交成功自动进入下一个未提交帧；完成按钮必须额外确认，不能因为浏览/播放/保存草稿而完成。

B 完成事务只读取每帧当前有效 submission，净差量按 A 对比当前 B 计算。多次修改同一对象只生成一个最终 change。零修改视频也固定完整 B，并生成 0 changes 的 C 任务。

### 草稿、断点、失败

- 松手保存，一次手势一个撤销步骤；当前帧最多 50 步，切帧清空 B 撤销栈。
- 默认进入首个未提交帧；独立保存每个用户最后浏览帧，并提示上次位置及草稿。恢复草稿不计提交。
- 写入串行；失败保留本地框与原幂等键，不推进帧、不显示“已保存”、不直接离页。优先原请求重试；冲突可备份本地 patch，再明确重新读取。
- 成功落库的草稿可刷新恢复；尚未发送/成功的编辑不保证异常断电恢复。关闭或刷新时用未保存提示保护用户。

## C：逐项决定、恢复与最终版本

视频状态 `pending → in_progress → confirmed`。领取不产生决定；浏览不选择；点击 A/B 即保存；自动下一项可关闭。最后一项选择后显示完成确认弹窗，关闭弹窗仍保留顶部完成入口。

- 待选数只统计 B 净变化；未修改对象自动沿用 A。
- `decisionRevision` 控制每项并发；决定保存后才能更新进度。可重选、撤销上一次选择；撤销历史存服务端，刷新后有效。
- 游标与业务版本独立；重进恢复上次项，也可跳到首个待选项。
- 未确认保存的操作按账号写入 `sessionStorage`；网络超时、响应丢失、刷新、重新登录后可用原键重放。409 时不能静默覆盖，应明确读取服务器状态。存储不可用时提示/记录失败，不承诺意图恢复。
- 全选 100% 仍需显式完成；**零修改视频同样需要显式完成**。
- 完成事务生成 F 的全部帧，含未修改帧、空帧和每个对象的 A/B/决定来源。历史 A/B/F 和决定事件保留。
- “重新确认”保留选择与历史 F，重新开放编辑；再完成生成新 F，旧 F 仍可追溯，但不能据旧 F 导出训练集。

### 退回本帧重审

C 在当前修改项 A/B 均不合适时，可填写原因退回其所在整帧。只有当前领取人可操作，版本/幂等校验与状态变更同事务。旧 C 置 `returned`、只读；原 B 回到 `in_progress`，仅该帧取消有效提交，保留原 submission 与 B 几何供继续检查。原 A、固定 B/C/F 和决定事件不改写。该帧恢复原几何或放弃草稿均不能恢复提交，必须重新显式提交；其他帧仍按正常草稿规则处理。

B 重新提交并完成视频后固定新 B 和新 C，由原确认人继续。其他帧存在性、类别、几何均未变化且已有决定的项以带源事件关联的新决定继承；退回帧的修改项全部重新选择。补标项 A 无/B 有，删除项 A 有/B 无；C 可采用/拒绝存在性变化。未变化项/空帧仍按原完整帧规则固定；新 C 仍需显式完成，即使重审后没有修改项。旧 C 提供新任务入口，可多轮退回。重审及再次确认完成前，旧训练包停止下载；旧审计证据不改变。

## 指标与坐标

B/C 使用原图连续像素 `bbox=[x1,y1,x2,y2]`；B 草稿标准化到 0.001 px。已有对象类别继承 A；对象存在性由 B 净变化与 C 决定确定。补标关联全视频已有身份或服务端分配的新身份，不能按列表位置分配/复用编号。API 帧号 0 起，页面 1 起。缩放、平移和裁剪仅改变显示。

- IoU = 交集面积 / 并集面积；连续坐标不加 1。B 未修改对象显示 `—`。平均 IoU 如用于统计只能计算修改框，页面不常驻展示该汇总。
- 中心位移 = `sqrt(Δcx²+Δcy²)`；最大位移如用于统计只取当前帧修改框，页面以选中对象详情为主。
- 宽高变化 = `B.width−A.width`、`B.height−A.height`，保留正负号；C 数据中同时保留中心 ΔX/ΔY，但确认页面不展示这些指标。
- 指标表示改动幅度，不能判定谁更准确；不计算 Precision/Recall。
- A/B 局部对比必须使用同一原图裁剪范围；C 完整帧上下文不随局部缩放裁掉目标。



# 已删除的 B/C 接口（原 API.md）

## A 完成与 B

实现：[review_workflow_routes.py](../backend/app/review_workflow_routes.py)、[reviewWorkflowApi.ts](../frontend/src/api/reviewWorkflowApi.ts)。前缀 `/api/review`。

| 方法与相对路径 | 请求/作用 |
| --- | --- |
| `GET /media/{mediaId}/completion-preview` | 来源 revision、有框/空/未知帧及未知范围 |
| `POST /media/{mediaId}/complete` | `expectedSourceRevision`、`confirmComplete`、`explicitEmptyFrameRanges:[{start,end}]`（0 起，含端点） |
| `GET /sessions`、`/sessions/{sid}` | 任务列表、详情 |
| `POST /sessions/{sid}/claim` | 原子领取，可自审 |
| `GET /sessions/{sid}/objects` | 全视频对象目录，`items:[{objectId,classKey,origin}]`；origin 为 baseline/review |
| `POST /sessions/{sid}/objects` | `expectedSessionRevision`、可选 `classKey`；保留新对象身份，返回 `{session,object}`，原键重放不再分配 |
| `POST /sessions/{sid}/return-annotation` | `expectedSessionRevision,reason`；当前审查员将进行中任务退回人工标注，旧任务只读、历史保留 |
| `GET /media/{mediaId}/submission-status` | `items` 为活动送审任务及 `canWithdraw`，排除已撤回/退回人工任务；`history` 提供退回人工任务及原因 |
| `POST /sessions/{sid}/withdraw` | `expectedSessionRevision`；仅送审者且审查尚未领取/编辑，保留 A、任务置 `withdrawn` |
| `POST /media/{mediaId}/reset-annotations` | `expectedRevision`、`confirmDiscard:true`；覆盖重新标注，已送审活动任务或 AI 运行时拒绝，返回工作区新 revision / generationId |
| `GET /sessions/{sid}/frames/{fi}` | A、当前有效框、草稿、上次成功提交、帧版本/权限 |
| `PUT /sessions/{sid}/frames/{fi}/draft` | `expectedFrameRevision`、`patch` |
| `POST /sessions/{sid}/frames/{fi}/submit` | `expectedFrameRevision`、`patch` |
| `POST /sessions/{sid}/frames/{fi}/discard` | `expectedFrameRevision`，恢复上次有效提交或 A |
| `POST /sessions/{sid}/freeze` | `expectedSessionRevision`，固定 B、changes、C 任务 |
| `PUT /cursors` | `sessionId`、`frameIndex`、`expectedCursorRevision` |

`patch` 是当前帧相对 A 的完整净差量，坐标为原图像素：`{objectId,bbox}` 默认为 update；`{op:"add",objectId,classKey,bbox}` 补当前帧；`{op:"delete",objectId}` 删除本帧。add 只能关联本任务全视频目录中的合法身份，重复身份、非法类别/坐标拒绝。新增 ID 先由 objects 接口分配，不能客户端猜号。唯一视频类别默认继承；多类别必须明确选择已有类别，全空 A 默认项目类别 rare sperm。已有对象类别不可改，不能因补标把 rare sperm 拆成另一类 sperm。A 不改写；净差量消失则无需 C 决定。

Session 关键字段：`id, baselineId, revision, state, reviewerId, media, progress, resume, permissions, readOnlyReason, completedReviewVersionId,submittedBy,withdrawalBlockedReason,returnAnnotation`。`permissions.canReturnAnnotation` 表示当前审查员是否可退回人工；`returnAnnotation` 含 reason/actorId/createdAt。`progress` 含 `submittedFrames/unsubmittedFrames/draftFrames/modifiedFrames/modifiedBoxes/percent`；`resume` 含最后浏览、首个未提交、草稿索引及游标版本。Frame 关键字段：`frameRevision/state/hasDraft/baselineObjects/effectiveObjects/patch/lastSubmission/permissions`。不要用 `lastSubmission != null` 推断当前已提交。

`resume.submittedFrameIndexes` 是由当前帧状态 `submitted` 投影出的只读 0 起索引数组，供审查帧条绘制已提交状态；它不是客户端提交进度的写入口。已提交帧重新编辑为草稿或被退回重审后，应从该数组移除，仍保留其历史 submission；放弃草稿恢复有效提交或重新提交成功后再出现。`resume.draftFrameIndexes` 表示当前草稿，退回标记来自退回记录，不能仅凭历史提交引用、当前浏览帧或帧条颜色判定视频已完成。

上传相同内容返回 409 `DUPLICATE_VIDEO`，正文 `{message,code,duplicate:{mediaId,videoName,canOverwrite,reason,workspaceRevision,media}}`；`media` 是现存源视频元信息，不会保存第二份上传。覆盖通过上表 reset 接口完成，使用原键原正文重试；目录与未撤回 A 的关联在服务端再次校验。已覆盖工作区 GET 带 generationId；旧无版本保存返回 428。该视频之后的人工记录、seed、rewind 和 Tracking 写请求携带当前 generationId，缺失或旧值返回 409，在修改文件/DB或清未来分支之前拒绝。尚未覆盖的旧工作区保持兼容。

Session 另带 `returnRequests:[{frameIndex,reason,confirmationId}]`，仅未解决的本帧重审请求。撤回后再次送审创建新 A/任务，不复用 `withdrawn` 或 `returned_to_annotation`；领取与撤回使用同一 SQL 事务竞争。

旧上传任意 frames 冻结 A 的路由不用于新流程；历史不完整来源只读，不能在前端填充假帧修复。

## C 与完整最终版本

实现：[confirmation_workflow_routes.py](../backend/app/confirmation_workflow_routes.py)、[confirmationApi.ts](../frontend/src/api/confirmationApi.ts)。前缀 `/api/confirmation`。

| `POST /sessions/{sid}/return` | `expectedSessionRevision`、`changeId`、`reason`（1–1000 字）；当前确认人将该项所在整帧退回原 B 重审 |
| `PUT /sessions/{sid}/cursor` | `changeId`、`expectedCursorRevision` |

`Change` 含 `changeId/frameIndex/objectId/annotationId/beforeBbox/afterBbox/changeKind/metrics/decisionRevision/decision`。`changeKind` 为 update/add/delete；beforeBbox 或 afterBbox 可为 JSON null，表示该版本不存在该框，不等于读取失败。增删项的几何指标为 null。C 不上传任意新 bbox 或类别，只选择 A/B 的框或明确不存在状态。`progress` 含 `totalChanges/decided/pending/keptA/adoptedB/percent`，零修改百分比不替代显式完成。

C 权限另带 `canReturn`；返回状态为 `returned`，`returnedReview:{frameIndex,reason,reviewSessionId,nextConfirmationId,reviewState,returnedToAnnotation,annotationReturnReason}|null` 指向原 B 及重审后新 C。旧 C 不再可编辑或完成。B 仅取消被退回帧的有效提交，保留旧 submission 与起始 B 几何；草稿/恢复不能代替重新显式提交。再次 freeze 固定新 B/C，其他帧存在性、类别、几何均未变且已有决定的项以带来源关联的新事件继承，退回帧不继承决定；新 C 保留原确认人。

新版 C 写请求携带 `X-Confirmation-Response: delta`。响应新增 `itemsScope:'changed'`：决定/撤销仅返回受影响项，游标/领取/完成/重新确认/退回返回空 `items`；完整 `session`、选中项、下个待选项仍返回。前端按 changeId 合并而不是替换全列表，检测到其他窗口的业务版本跳变时重新 GET session/changes。无 header 的旧客户端仍返回全量列表。幂等回执保存首次响应，重试返回同一响应形态；新版能重放升级前的全量回执。响应模式不改变原请求业务 hash，不删除历史决定或旧回执。会话统计与下个待选项通过 SQL 计算，不为浏览位置反复解码全视频几何。

`GET /api/final-versions/{id}` 和 `/{id}/download` 提供完整 JSON。每帧存在，包括空 `objects:[]`；对象保留稳定身份、类别、最终框、A/B 框及 `choice/resolution/changeId/decisionEventId`。未改对象 `choice:null`、`resolution:'unchanged'`，来源 A。完整帧表不能用仅有对象的表代替，否则会丢空帧。被确认删除/拒绝补标的对象不进入最终帧 objects，但独立决定记录及统计/训练审计仍保留其事件与两侧状态。
