# 0001 多人协作工作区合并

- 日期：2026-11-01
- 状态：采用

## 背景

整个视频共用带版本的工作区。观看状态也写入共享资源时，只浏览同一视频也会增加版本冲突。强制下载 JSON 再重读将防丢细节转嫁给使用者。

## 决定

个人观看状态留在本机。基于各客户端已读取的独立基准，以帧号与稳定对象身份做三方合并；共享资源的最终写入仍由原服务端版本、来源锁和事务校验。只有确定性的版本拒绝才可读取新基准并生成新键；结果不确定必须先确认原请求。删除与同一身份的修改一并决策，不能仅合并数组后让墓碑悄悄抹掉选中的框。

恢复使用 IndexedDB，避免大视频草稿受到小容量 Web Storage 配额限制；按页面、账号和视频隔离，跨刷新恢复原键。冲突明确保留双方，JSON 改为按需导出。

## 放弃的方案及原因

- 不取消版本检查或采用最后写入覆盖：会丢失他人修改。
- 不锁住整个视频让其他人不能看：不符合多人协作需求。
- 不引入多 worker、WebSocket 协同或 CRDT：本次不改变单进程发布与恢复架构。空闲轮询用于接收远端更新，写入时的版本检查承担正确性保证。
- 不把 AI 发布、回退、覆盖重标当作普通框合并；generation 更换与专用动作仍保留明确边界。

## 影响

当前规则见 WORKFLOW、API、STORAGE_LAYOUT，操作见用户说明，验证入口见 TESTING。后端数据格式与离线存储兼容契约保持不变。
